# COLLEGE EVENT MANAGEMENT SYSTEM

## Project Plan

*A centralized platform for college event organization and management*

---

## 1. Project Overview

The College Event Management System is intended to provide a centralized platform for managing college events and participant registrations. Students will be able to browse events, view event details, register, check registration status, and access certificates when issued. Event organizers will be able to create, update, and cancel events, manage participants, and handle event schedules, venues, and certificates.

This project plan defines the objectives, scope, team responsibilities, deliverables, proposed milestones, execution approach, monitoring process, assumptions, constraints, and success criteria for the project.

## 2. Project Objectives

The main objectives are to:

- Provide a centralized place to view available college events.
- Allow students to view event information and register for events.
- Prevent duplicate registrations for the same event.
- Enable organizers to create, update, and cancel events.
- Help organizers manage event participants, schedules, and venues.
- Support issuing certificates to eligible participants.
- Allow students to view and download certificates that have been issued.
- Coordinate project work through clear task ownership, milestones, and progress tracking.

## 3. Project Scope

### 3.1 In Scope

The project includes the following functionality:

- Display a list of available events.
- Display event details.
- Allow students to register for events.
- Prevent duplicate registrations.
- Allow organizers to create, update, and cancel events.
- Allow organizers to view and manage participant lists.
- Manage event schedules and venue information.
- Issue certificates to eligible participants.
- Allow students to view and download their certificates.
- Provide login functionality where required by the agreed implementation.

### 3.2 Out of Scope

The following features are not included in the current project scope:

- Online payments or payment gateway integration.
- QR-code-based attendance verification.
- AI-based event recommendations.
- Dedicated mobile applications.
- External SMS notification integration.

Any change to the agreed scope should be discussed by the team and recorded before implementation.

## 7. Execution Approach

The project will be carried out through the following work phases:

### Phase 1: Requirements and Analysis

- Review the project requirements and expected system functionality.
- Identify the stakeholders and their responsibilities.
- Document functional and non-functional requirements.
- Review use cases, user stories, and acceptance criteria.
- Share the requirements with the design and development team.

### Phase 2: System and Database Design

- Prepare the proposed system architecture.
- Design the user interface and main application screens.
- Identify the required data entities and relationships.
- Prepare the database structure.
- Review the design against the agreed requirements.

### Phase 3: Development

- Implement the agreed application features.
- Connect the application interface with the backend and database.
- Implement student and organizer workflows.
- Keep implementation aligned with the agreed project scope.

### Phase 4: Testing and Review

- Test the main student and organizer workflows.
- Check registration and duplicate-registration handling.
- Verify event creation, updating, and cancellation.
- Check participant management and certificate access.
- Record defects and track their resolution.

### Phase 5: Project Management and Documentation

- Maintain the project plan, WBS, Gantt chart, and risk register.
- Track task ownership, status, due dates, and blockers in Jira.
- Coordinate with team members on progress and dependencies.
- Collect and review the individual deliverables.
- Compile the final documentation and presentation materials.

Some phases may overlap where appropriate, but work with dependencies should follow the required order. For example, implementation should use the agreed requirements and design as its reference.

## 8. Project Monitoring and Control

Project progress will be monitored using Jira and the team's shared project repository.

### 8.1 Task Tracking

Each task should have:

- A clear title and description.
- An assigned owner.
- A due date, where applicable.
- A status showing current progress.
- Relevant dependencies or blockers.
- Links to the related deliverable or documentation.

### 8.2 Progress Monitoring

- Review Jira task status regularly.
- Follow up on overdue tasks and blocked work.
- Coordinate with the responsible team member when a dependency affects progress.
- Update milestone dates when changes are agreed.
- Keep project documents consistent with the latest decisions and implementation status.

### 8.3 Communication and Records

The team should use agreed communication channels for coordination. Important decisions, action items, and changes to scope or schedule should be recorded so that all team members can refer to the same information.

## 9. Assumptions

The project plan is based on the following assumptions:

- The system is being developed as a prototype.
- The primary user roles are students and event organizers.
- Administrator functionality is optional and depends on the agreed implementation.
- Event organizers determine participant eligibility for certificates.
- QR-code attendance verification is not part of the current scope.
- The technology stack and detailed architecture will be determined through the design and development work.
- The proposed milestone dates will be confirmed by the team.

## 10. Constraints

- The project must be completed within the team's agreed timeline.
- Development should remain aligned with the documented requirements and scope.
- Team members have separate responsibilities, so tasks may depend on outputs from other members.
- Changes to requirements or implementation may affect the schedule and should be communicated.
- The current scope excludes the features listed in Section 3.2.

## 11. Success Criteria

The project will be considered successful when:

- The agreed core requirements are implemented.
- Students can browse events, view details, and register.
- Duplicate registrations are prevented.
- Organizers can manage events and participants.
- Event schedules and venues can be maintained.
- Eligible participants can be issued certificates and students can access issued certificates.
- The implemented workflows have been tested and reviewed.
- Project tasks and risks have been tracked.
- Required documentation and presentation materials are complete and reviewed by the team.
