# REST API Contract — College Event Management System

This document specifies the exact REST API contract established between the **Frontend (React + Vite)** running on `http://localhost:5173` and the **Backend (Node.js + Express + Prisma + PostgreSQL)** running on `http://localhost:3000`.

---

## 1. Global Conventions

- **Base URL:** `http://localhost:3000/api`
- **Data Format:** `application/json` for all request bodies and responses
- **Date Format:** ISO 8601 strings (e.g., `2026-11-28T09:00:00.000Z`)
- **Authentication Scheme:** HTTP Bearer token in the `Authorization` header:
  ```http
  Authorization: Bearer <jwt_token>
  ```
- **Standard Success Response Shape:**
  ```json
  {
    "success": true,
    "data": { ... },
    "message": "Operation completed successfully"
  }
  ```
- **Standard Error Response Shape:**
  ```json
  {
    "success": false,
    "message": "Human-readable description of error",
    "errors": [ ... ]
  }
  ```

---

## 2. Approved 5-Entity Database Schema Mapping

| Entity | Fields & Types | Frontend Handling |
|---|---|---|
| **USERS** | `id`, `name`, `email`, `student_id_number`, `password_hash`, `role`, `department`, `created_at`, `status` | `password_hash` is **never** sent to or received by the frontend. `role` is strictly `STUDENT`, `ORGANIZER`, or `ADMIN`. |
| **VENUES** | `id`, `name`, `location`, `capacity`, `status` | Capacity is validated on the frontend when organizers set `max_participants`. |
| **EVENTS** | `id`, `title`, `description`, `organizer_id`, `venue_id`, `start_time`, `end_time`, `registration_deadline`, `max_participants`, `status`, `cancel_reason`, `category`, `created_at`, `updated_at` | `status` is one of `DRAFT`, `PUBLISHED`, `CANCELLED`, `COMPLETED`. |
| **REGISTRATIONS** | `id`, `event_id`, `student_id`, `status`, `certificate_eligible`, `registered_at` | `status` is one of `CONFIRMED`, `CANCELLED`, `ATTENDED`, `WAITLISTED`. |
| **CERTIFICATES** | `id`, `registration_id`, `certificate_no`, `file_path`, `issued_at`, `issued_by` | Generated by administrators for students marked `ATTENDED`. |

## 3. API Endpoints Specification

### 3.1 Authentication (`/api/auth`)

#### `POST /api/auth/login`
- **Description:** Authenticates user and returns JWT token + user profile with role.
- **Request Body:**
  ```json
  {
    "email": "student@apex.edu",
    "password": "password123"
  }
  ```
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "token": "eyJhbGciOiJIUzI1NiIsIn...",
    "user": {
      "id": "u-1",
      "name": "Alex Rivera",
      "email": "student@apex.edu",
      "student_id_number": "STU-2024-001",
      "role": "STUDENT",
      "department": "Computer Science & Engineering",
      "status": "ACTIVE",
      "created_at": "2026-08-15T09:00:00Z"
    }
  }
  ```
- **Error Codes:** `401 Unauthorized` (Invalid credentials), `403 Forbidden` (Account deactivated).

#### `POST /api/auth/register`
- **Description:** Public student registration. The backend must enforce role = `STUDENT`.
- **Request Body:**
  ```json
  {
    "name": "Jordan Lee",
    "email": "jordan.lee@apex.edu",
    "student_id_number": "STU-2024-089",
    "department": "Information Technology",
    "password": "securePassword123"
  }
  ```
- **Response (201 Created):**
  ```json
  {
    "success": true,
    "token": "eyJhbGciOiJIUzI1NiIsIn...",
    "user": {
      "id": "u-99",
      "name": "Jordan Lee",
      "email": "jordan.lee@apex.edu",
      "student_id_number": "STU-2024-089",
      "role": "STUDENT",
      "department": "Information Technology",
      "status": "ACTIVE",
      "created_at": "2026-11-14T10:00:00Z"
    },
    "message": "Student account registered successfully"
  }
  ```
- **Error Codes:** `400 Bad Request` (Duplicate email or Student ID).

#### `GET /api/auth/me`
- **Description:** Fetches current authenticated user profile using Bearer token.
- **Headers:** `Authorization: Bearer <token>`
- **Response (200 OK):** `{ "success": true, "user": { ... } }`

#### `POST /api/auth/logout`
- **Description:** Revokes current session/token.
- **Response (200 OK):** `{ "success": true, "message": "Logged out successfully" }`

### 3.2 User Management (`/api/users`)

#### `GET /api/users`
- **Access:** `ADMIN`
- **Query Params:** `role` (optional), `department` (optional), `search` (optional)
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "data": [
      {
        "id": "u-2",
        "name": "Prof. Priya Sharma",
        "email": "organizer@apex.edu",
        "student_id_number": null,
        "role": "ORGANIZER",
        "department": "Information Technology",
        "status": "ACTIVE",
        "created_at": "2026-07-10T10:30:00Z"
      }
    ],
    "total": 6
  }
  ```

#### `POST /api/users`
- **Access:** `ADMIN` (Provisions new faculty organizers or admin accounts)
- **Request Body:** `{ "name": "...", "email": "...", "role": "ORGANIZER", "department": "...", "student_id_number": null }`

#### `PUT /api/users/:id`
- **Access:** `ADMIN` or profile owner

#### `PATCH /api/users/:id/role`
- **Access:** `ADMIN`
- **Request Body:** `{ "role": "ORGANIZER" }`

#### `PATCH /api/users/:id/status`
- **Access:** `ADMIN`
- **Description:** Toggles active / inactive status.

### 3.3 Event Management (`/api/events`)

#### `GET /api/events`
- **Access:** Public / Authenticated
- **Query Params:** `status`, `category`, `venue_id`, `organizer_id`, `search`, `sortBy`
- **Response (200 OK):**
  ```json
  {
    "success": true,
    "data": [
      {
        "id": "e-1",
        "title": "HackGenesis 2026",
        "description": "24-Hour National Hackathon...",
        "organizer_id": "u-2",
        "venue_id": "v-2",
        "category": "Technical & Coding",
        "start_time": "2026-11-28T09:00:00Z",
        "end_time": "2026-11-29T12:00:00Z",
        "registration_deadline": "2026-11-25T23:59:00Z",
        "max_participants": 100,
        "status": "PUBLISHED",
        "cancel_reason": null,
        "venue": { "id": "v-2", "name": "Tech Innovation Hall", "capacity": 120 },
        "organizer": { "id": "u-2", "name": "Prof. Priya Sharma" },
        "registered_count": 42,
        "available_seats": 58
      }
    ]
  }
  ```

#### `GET /api/events/:id`
- **Response (200 OK):** Detailed event with populated venue and organizer.

#### `POST /api/events`
- **Access:** `ORGANIZER`, `ADMIN`
- **Request Body:**
  ```json
  {
    "title": "Robotics Expo",
    "description": "Hands-on exhibition...",
    "venue_id": "v-1",
    "category": "Technical & Coding",
    "start_time": "2026-12-01T10:00:00Z",
    "end_time": "2026-12-01T17:00:00Z",
    "registration_deadline": "2026-11-29T23:59:00Z",
    "max_participants": 200,
    "status": "DRAFT"
  }
  ```

#### `PUT /api/events/:id`
- **Access:** Assigned `ORGANIZER` or `ADMIN`

#### `PATCH /api/events/:id/publish`
- **Access:** Assigned `ORGANIZER` or `ADMIN`
- **Sets:** `status = 'PUBLISHED'`

#### `PATCH /api/events/:id/cancel`
- **Access:** Assigned `ORGANIZER` or `ADMIN`
- **Request Body:** `{ "cancel_reason": "Inclement weather alert" }`

### 3.5 Registration Management (`/api/registrations`)

#### `GET /api/registrations`
- **Access:** Filtered by user permissions:
  - `STUDENT`: returns student's own registrations.
  - `ORGANIZER`: returns registrations for events owned by organizer.
  - `ADMIN`: returns all registrations.
- **Query Params:** `student_id`, `event_id`, `status`

#### `POST /api/registrations`
- **Access:** `STUDENT`
- **Request Body:** `{ "event_id": "e-1" }`
- **Rules Enforced by Backend:**
  - Event must have `status === 'PUBLISHED'`
  - Current timestamp must be `<= registration_deadline`
  - Total active registrations must be `< max_participants`
  - Student must not have an active confirmed registration for this event.

#### `PATCH /api/registrations/:id/cancel`
- **Access:** Registering student or `ADMIN`
- **Sets:** `status = 'CANCELLED'` and releases seat back to capacity.

#### `PATCH /api/registrations/:id/attendance`
- **Access:** `ORGANIZER` or `ADMIN`
- **Request Body:** `{ "attended": true }`
- **Sets:** `status = 'ATTENDED'` and `certificate_eligible = true`.

---

### 3.6 Certificate Management (`/api/certificates`)

#### `GET /api/certificates`
- **Query Params:** `student_id` (optional)
- **Response (200 OK):** Array of certificates with `certificate_no`, `file_path`, `issued_at`, `student`, and `event`.

#### `POST /api/certificates/issue`
- **Access:** `ADMIN`
- **Request Body:** `{ "registration_id": "r-3" }`
- **Rules:** Registration must have `status === 'ATTENDED'`, generates unique `certificate_no` (e.g., `AIT-CERT-2026-XXXX`).

#### `GET /api/certificates/:id/download`
- **Response:** PDF file or JSON with pre-signed download URL.

---

### 3.7 Reports & Analytics (`/api/reports`)

#### `GET /api/reports/dashboard`
- **Response:** KPI counts for Users (total, students, organizers, admins), Events (total, published, drafts, completed, cancelled), Registrations, Certificates, and Venues.

#### `GET /api/reports/analytics`
- **Response:** Time-series registration counts, events by status, popular events, department distribution, venue utilization rates.
